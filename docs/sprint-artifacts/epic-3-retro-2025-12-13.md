## Key Learnings

### PS5.1 Compatibility Patterns (Standard Going Forward)

1. **ValidateScript without ErrorMessage:**
   ```powershell
   # PS7+ only (DON'T USE):
   [ValidateScript({ $_.Trim().Length -gt 0 }, ErrorMessage = 'Text cannot be empty')]

   # PS5.1 compatible (USE THIS):
   [ValidateScript({
       if ($_.Trim().Length -eq 0) {
           throw 'Text cannot be empty'
       }
       $true
   })]
   ```

2. **Pester 3.4 syntax** (not Pester 5):
   - `Should Be` not `Should -Be`
   - `Should Throw` not `Should -Throw`
   - `Assert-MockCalled` not `Should -Invoke`

### ADF Structure Patterns

1. **Document root:** `@{ version = 1; type = 'doc'; content = @() }`
2. **Content nodes must have `type` property**
3. **Text nodes:** `@{ type = 'text'; text = 'content' }`
4. **Marks for formatting:** `@{ type = 'strong' }` or `@{ type = 'em' }`
5. **Tables require:** tableRow -> tableCell -> paragraph -> text chain

### Private Function Testing

- Use `InModuleScope` for module-scoped variable access
- Dot-source Private functions directly in test files
- Integration tests can chain multiple Private functions

## CIPP User Data Research (Epic 4 Preparation)

During the retrospective, comprehensive research was conducted on CIPP's user data structures to prepare for Epic 4: User Data Sync.

### CIPP API Endpoints Discovered

| Endpoint | Purpose | Data Returned |
|----------|---------|---------------|
| `/api/ListUsers` | User list | Basic user properties |
| `/api/ListGraphRequest` | Graph API proxy | Full user properties with $select |
| `/api/ListGraphBulkRequest` | Batch Graph calls | Multiple resources per user |
| `/api/ListMFAUsers` | MFA report | MFA registration status |
| `/api/ListLicenses` | License inventory | SKU names and counts |

### User Properties Available (from Graph API)

**Identity:**
- `id`, `displayName`, `givenName`, `surname`
- `userPrincipalName`, `mail`, `mailNickname`, `userType`

**Account Status:**
- `accountEnabled`, `isResourceAccount`

**Contact:**
- `businessPhones`, `mobilePhone`, `faxNumber`, `otherMails`

**Organization:**
- `companyName`, `department`, `jobTitle`

**Licensing:**
- `assignedLicenses` (array of SKU IDs)

**Timestamps:**
- `createdDateTime`
- `onPremisesLastSyncDateTime`

### Last Sign-In Data Pattern

CIPP fetches sign-in logs via bulk request:
```json
{
  "id": "signInLogs",
  "url": "/auditLogs/signIns?$filter=(userId eq '{userId}')&$top=1",
  "method": "GET"
}
```

**Performance Consideration:** Requires per-user API call. For 100 users = 100 additional API calls.

**Recommendation:** Make last sign-in an optional parameter in Story 4.1.

### Existing Reference Patterns

The `scripts/update-client-environment-from-cipp.ps1` file (1211 lines) provides an excellent reference:

1. **User filtering:** Excludes guest accounts (`userType -ne "Guest"`)
2. **MFA merge:** Joins user data with MFA report by UPN
3. **License lookup:** Matches `assignedLicenses.skuId` to `skuPartNumber`
4. **Table generation:** Converts to Confluence Storage Format tables

Key code sections:
- Lines 399-461: User data transformation with MFA merge
- Lines 413-439: License name lookup pattern
