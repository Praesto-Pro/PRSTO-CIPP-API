## Challenges

### Story 8.4 Required Two Code Reviews

**Issue:** First review passed, but second review found real code quality issues

**What Review #1 Caught:**
- Documentation completeness (tasks marked done, File List populated)

**What Review #2 Caught:**
| Severity | Issue | Impact |
|----------|-------|--------|
| MEDIUM | SHA256 object not disposed | Resource leak in long sessions |
| MEDIUM | Duplicate cache init in 5 files | DRY violation |
| MEDIUM | Epic 8 status still "in-progress" | Status tracking oversight |
| LOW | Misleading docstring | Documentation inaccuracy |
| LOW | No volatile state warning | User documentation gap |

**Root Cause:** Review #1 was checklist-focused, not adversarial. Different review depths, not two passes at the same review.

**Learning:** Unit tests + PSScriptAnalyzer ≠ production readiness. Resource leaks and code quality issues can pass automated checks.

### No Integration Testing Yet

- All 1,331+ tests are unit tests with mocks
- Haven't tested against real Confluence APIs
- README documents integration test process, but not executed

---

## Lessons Learned

1. **Checklist reviews ≠ adversarial reviews** - Need both: checklist for completeness, adversarial for quality

2. **Unit tests have blind spots** - SHA256 disposal issue passed all tests and linting

3. **Layered architecture accelerates delivery** - Clear dependencies between stories reduced friction

4. **In-memory state is acceptable with documentation** - Volatility documented clearly in help text
