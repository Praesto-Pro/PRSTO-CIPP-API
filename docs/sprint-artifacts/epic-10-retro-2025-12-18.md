## Challenges

### Speed + Reference Pattern Created Dependency Risk
- **Challenge:** Team adopted Hudu pattern wholesale without validating reference quality first
- **Context:** Matthias noted Epic 10 planning felt "scrambled" - went from Epic 9 retro discovery to Story 10.1 execution quickly
- **Risk:** If Hudu had architectural issues, Epic 10 would have inherited them
- **Outcome:** Hudu pattern was solid, but we got lucky - no validation gate existed
- **Lesson:** Reference patterns accelerate work but should be validated before wholesale adoption

### PowerShell 5.1 Compatibility Added Development Overhead
- **Affected Stories:** 10.3 (Configuration Management), 10.4 (Cache Integration)
- **Issues:**
  - No `ConvertFrom-Json -AsHashtable` in PS 5.1 → required manual hashtable conversion
  - No null coalescing operator (`??`) → required verbose `if/else` blocks
- **Impact:** Slower development, more verbose code, additional boilerplate
- **Mitigation:** Patterns documented in dev notes, no bugs introduced
- **Context:** PS 5.1 support transitional - CIPP moving to PS 7 but can't assume all deployments upgraded
- **Action Item:** Document PS 5.1 patterns for future reference (Elena + Charlie)

### Pester 3.4 Mock Accumulation Required Test Cleanup
- **Affected Story:** 10.1 (Extension Sync Orchestrator)
- **Issue:** Mock call counts accumulated across test contexts - 90/111 tests passing initially
- **Root Cause:** Pester 3.4 doesn't reset mocks properly between contexts
- **Resolution:** Careful `BeforeEach` cleanup, not a code bug
- **Context:** CIPP uses Pester 3.4 for compatibility, can't upgrade to Pester 5 without migrating entire test suite
- **Impact:** Added complexity to test setup, required trial-and-error debugging

### Code Review Patterns Revealed Recurring Gaps
- **Parameter Type Constraints:** Missing `[hashtable]` in Story 10.1 - caught in review
- **Return Object Consistency:** Cache hits returning `$null` in Story 10.4 - caught in review
- **WhatIf/ShouldProcess Compliance:** `Get-CIPPTable` inside ShouldProcess block (Story 10.4) - caught in review
- **Task Checklist Accuracy:** Tasks marked `[ ]` when status was `done` - caught in review
- **Pattern:** Same types of issues across multiple stories (parameter types, return values, -WhatIf support)
- **Analysis:** These are PowerShell best practices easy to miss during fast development, not design flaws
- **System Working:** Code review caught all 15+ issues before merge

### Story 10.5 Title Implied Implementation But Scope Was Verification
- **Issue:** Story title "API Key Framework Integration" implied building the integration
- **Reality:** Integration already complete in Story 10.1, Story 10.5 was verification/testing/documentation
- **Impact:** Minor confusion about scope when reading story board
- **Resolution:** Acceptance criteria were clear (verification-focused), no functional issues
- **Action Item:** Create story title guidelines distinguishing implementation vs. verification (Alice)

## Lessons Learned

1. **Upfront research accelerates execution and prevents mid-sprint confusion** - Epic 9 retro research provided clear Epic 10 direction. Investment in research pays dividends during implementation.

2. **Reference patterns enable speed but create dependency on reference quality** - Hudu pattern accelerated Epic 10 dramatically, but team didn't validate reference before adopting wholesale. Worked out because Hudu was solid, but risky approach.

3. **Planning embedded in retrospectives works for specific contexts** - Epic 10 planning happened in Epic 9 retro. Felt "scrambled" but worked because scope was clear and reference pattern existed. Not a pattern to generalize.

4. **Two-stage quality gates catch different issue types** - Unit tests catch functional bugs, code reviews catch standards/best practices. Both needed. ~15 review issues found across 5 stories, all caught before merge.

5. **Strong test coverage ≠ production readiness** - 200+ tests give confidence in logic, but don't replace live environment validation. Mocked tests can't catch network issues, real API behavior, edge cases in production data.

6. **Compatibility constraints (PS 5.1, Pester 3.4) are ecosystem decisions** - Not Confluence-specific problems. CIPP transitioning to PS 7 and newer Pester, but can't assume all deployments upgraded. Workarounds functional but add overhead.

7. **Extensible architecture minimizes integration cost** - Story 10.2 required one line of code because framework was well-designed. Proof that upfront architecture investment pays off.
